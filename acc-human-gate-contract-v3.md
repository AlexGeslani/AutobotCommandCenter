# Autobot Command Center — Human-Gate Contract v3

Status: Implemented as a fixture-backed Hermes plugin candidate
Date: 2026-07-26

## Product sentence

The Autobot Command Center is a read-only, mobile-first visual projection of what the system has produced, what verified evidence established, and what is available now.

It is not a Wiki, task manager, session browser, benchmark launcher, or second configuration surface.

## Durable information architecture

1. **Overview** — recently landed outcomes, current durable capabilities, separate model leaders by domain, and only evaluations awaiting a named decision.
2. **Portfolio** — products and capabilities with operating envelope, limitations, evidence, and attached evaluation timeline.
3. **Benchmarks / Model Observatory** — release-scoped rankings whose row identity is an exact tested condition, with family and run lineage.
4. **Skill Registry** — only authored or materially maintained reusable artifacts, with separate provenance, stewardship, publication, and validation states.

Evaluations are not a fifth primary destination. A secondary Evidence index provides cross-domain discovery while each record remains attached to affected objects.

## Model evidence identity

```text
Model family
  └── Tested condition
       └── Canonical result for benchmark release
            └── Supporting run or aggregated runs
```

A ranked result belongs to:

```text
tested condition × benchmark release × canonical result
```

Current availability is never inferred from historical tested performance.

## Capability rollup policy

The Model Observatory may show a transparent cross-domain capability index only under this fixture policy:

- Exact tested conditions are the ranked identity.
- Only canonical results from the current allowlisted release for each domain participate.
- For each domain, a condition score is normalized as `condition score ÷ best observed canonical score for that exact release × 100`.
- The displayed index is the equal-weight average of represented domain-normalized values.
- Complete coverage is ranked separately from partial coverage.
- Missing or ambiguous canonical evidence is `Unknown`, never zero, and partial conditions are not cross-ranked with complete conditions.
- The index is evidence-relative, not a universal intelligence, readiness, availability, or future-performance claim.

## Human-gate scope

The candidate must prove:

- Native Hermes-shell fit without overriding Hermes Overview.
- Four bounded local destinations.
- Ten-second discovery of landed outcome, capability, domain leader, and pending decision.
- One action from leaderboard row to exact condition and one further action to run evidence.
- Global and object-attached evaluation discovery.
- Stable deep links and browser Back behavior.
- Mobile composition at 390px without primary horizontal scrolling.
- Non-color encoding for fresh, stale, missing, unknown, unavailable, provisional, and canonical states.
- Explicit fixture labeling so prototype data cannot be mistaken for canonical facts.

## Explicit exclusions

- Next Bets and parked-opportunity inventories.
- Compare and benchmark-release browser.
- Complete model-universe or adopted-skill mirroring.
- Generic work-in-flight or health monitoring.
- Opaque universal-model or synthetic readiness scoring.
- Unauthoritative cost or resource fields.
- Production adapters or any mutation control.
- Public-internet exposure.

## Bounded provider-usage exception

The explicit provider-usage MVP is an authorized subordinate Overview projection, not a fifth destination or a generic quota dashboard.

- **Codex/ChatGPT entitlement:** only the installed signed-in Codex app-server read contract may provide subscription-window data.
- **Claude Code entitlement:** only documented status-line `rate_limits` events may provide subscription-window data. Installing the ACC-owned status-line sink is a separate, reversible human-approved configuration change; ACC must not rewrite Claude settings silently.
- **Antigravity consumer quota:** render `Unsupported — no supported API` with capability/manual guidance. Do not scrape TUI output, private localhost RPCs, process arguments, OAuth, or Google private APIs.
- **Authority separation:** subscription quota, local client activity, organization billing, and estimates are separate metric classes. MVP renders subscription quota only and never averages provider windows.
- **Projection boundary:** a local model-free collector may publish one atomic, schema-allowlisted, redacted snapshot. The browser must never read client logs, home-directory caches, shell output, credentials, account identity, prompts, project identifiers, or raw provider responses.
- **Required states:** `fresh`, `stale`, `expired`, `inactive`, `not_yet_observed`, `unsupported`, `unknown`, `error`, `auth_error`, and `not_configured` are distinct. Missing or unavailable data is never rendered as zero, healthy, unlimited, current, or free.
- **MVP exclusions:** no transcript analytics, local activity history, estimated cost, admin billing APIs, alerts, database, public exposure, Caddy changes, account switching, or provider/account mutation.

## Post-gate source contract

No production datum may ship without exactly one named authority, freshness rule, unavailable/stale behavior, stable identity, and adapter owner. Missing authority renders as Unknown or removes the field; ACC never becomes the compensating truth store.
